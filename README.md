## 👋 Hey, I'm Vijay

I'm moving deliberately toward **Forward Deployed Engineering and GenAI Engineering**.

What excites me is the space between an idea and a working system:

> **Understand the problem → build something useful → put the pieces together → find what breaks → make it better.**

My current playground is a mix of:

**🐍 Python + ⚡ FastAPI + 🧠 GenAI + 🔎 RAG + 🤖 Agents + 🐳 Docker + ☸️ Kubernetes**

I'm not treating this as a title I already have.

**I'm building toward it in public, one project at a time.**

Instead of collecting frameworks, I'm trying to understand the engineering underneath them:

- How do we turn an ambiguous problem into a useful technical solution?
- Where does an AI system actually fail?
- How should retrieval be designed?
- How do agents make decisions and use tools?
- How do we validate model output?
- What changes when an application leaves the notebook?
- How do APIs, containers, databases and AI components fit together?
- How do we debug the system when the happy path stops working?

# 🧭 My FDE Direction

### Why does FDE interest me?

Because it sits at an interesting intersection:

<div align="center">

**🗣️ Understand people & problems**

⬇️

**🧩 Translate problems into technical solutions**

⬇️

**💻 Build & integrate**

⬇️

**🔧 Debug what doesn't work**

⬇️

**🚀 Deploy & iterate**

</div>

My background gives me experience being close to real software problems.

My current projects are where I'm adding the next layer:

**Python → Backend → GenAI → Agents → Deployment**

That's the transition I'm actively working on.

<details>
<summary>🔍 <b>What "FDE mindset" means to me</b></summary>

<br/>

### 01 — Start with the problem
Not "Which framework should I use?"

First: **What are we actually trying to solve?**

### 02 — Prototype quickly
Get something working early enough to discover what I don't understand.

### 03 — Get technical
APIs, databases, retrieval, schemas, tools, containers, logs.

### 04 — Get close to failure
The interesting engineering usually starts when the happy path ends.

### 05 — Iterate with evidence
Test it. Observe it. Fix it. Document what changed.

</details>
